Phase 11 — NL2SQL context wiring: make schema-grounded SQL generation real.

The gap: the NL2SQL agent generates SQL with zero schema context and zero few-shot examples (both retrieval stubs return [] and nothing calls them); the golden eval never noticed because it mocks the LLM. Everything needed already exists unused: schema_embeddings + agent_examples tables (pgvector, RLS-scoped), unused cache methods (get/set_schema_context, CacheTTL.SCHEMA_EMBEDDINGS), and a connector that already sets the tenant GUC.

## 1. Embedding provider (`backend/app/core/embeddings.py`, new)
- `embed_text(text) -> list[float]` via `openai.AsyncOpenAI` — model `text-embedding-3-small` (1536 dims, matching the VECTOR(1536) columns; the current `claude-embeddings-20250219` call targets a nonexistent API).
- Config: `OPENAI_API_KEY`, `EMBEDDING_MODEL` (default text-embedding-3-small), `EMBEDDING_DIMS` (1536). Clear error without a key; callers fail open.
- `.env.example` + `gen-env.sh` gain the OPENAI key placeholder (like ANTHROPIC's).

## 2. Retrieval service (`backend/app/services/schema_retrieval.py`, new)
- `retrieve_schema_context(query, tenant_id, top_k=5)`: embed query → pgvector cosine top-k on schema_embeddings via `PostgreSQLConnector(settings.DATABASE_URL, tenant_id=...)` (RLS+GUC tenant-scoped; SELECT passes the read-only gate) → map to the prompt's exact shape: `{table_name: full_name ("public.sales"), columns: columns_json, description}` (columns_json maps 1:1 to what `_build_user_message` renders). Fail-open: any error → [] with a warning (matches the metric-context pattern).
- `retrieve_few_shot_examples(query, tenant_id, top_k=3)`: same pattern on agent_examples (agent_name='nl2sql') → `[{nl_query, expected_sql}]`. No ivfflat index there — seq-scan fine at this scale, noted in code.
- SQL: named params with `:emb::vector(1536)` cast (string form), `ORDER BY embedding <=> :emb::vector(1536) LIMIT :k`, `WHERE embedding IS NOT NULL`.
