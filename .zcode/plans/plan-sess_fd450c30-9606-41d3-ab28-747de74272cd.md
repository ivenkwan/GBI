## 1. Audit writer via the existing LLMClient hook (the documented "every LLM call" contract)
- `app/core/llm_client.py` `_audit()` fix: hash the actual prompt (`sha256(messages)`) instead of model+token counts (docs promise "SHA-256 of prompt"); pass `messages` into `_audit`.
- `app/services/audit.py` (new): `write_audit_entry(entry)` — asyncpg connect on a DSN derived from `settings.DATABASE_URL` (driver normalized to plain postgresql; runtime creds are already genbi_app), `set_config('app.current_tenant_id', tenant)`, transaction, inline-literal INSERT with `$n::uuid` params. Rows with non-UUID `user_id`/`tenant_id`/`session_id` (the "unknown"/"default" fallbacks) are skipped with a warning; everything fail-open (log + continue, per docs/core-services.md).
- Wire once at startup: `create_app()` registers `get_llm_client().set_audit_callback(write_audit_entry)` — every pipeline LLM call (router/nl2sql/chart/narrative) lands a row with real token counts, latency, model name, and generated SQL. Matches ADR 002's agent-granularity audit goal.

## 2. Login rate limiting (failed-attempt counter on the auth oracle)
- `cache.py`: `register_failed_login(email) -> count` (Redis INCR + EXPIRE 900s on first, mirroring the existing unused `check_rate_limit` pattern), `login_failures(email) -> int`, `clear_failed_logins(email)`. Key `genbi:loginfail:{normalized_email}`. L2-only, fails OPEN when Redis is down (availability over lockout).
- Config: `LOGIN_MAX_FAILURES=5`, `LOGIN_LOCKOUT_SECONDS=900`.
- `auth.py`: after email normalization → `>= max` → 429 `{"detail": {"code": "TOO_MANY_ATTEMPTS", ...}}` (generic message); every 401 path registers a failure; success clears. CI-safe by design: test_auth accumulates only 3 failures on the shared email (verified by research), under the 5 threshold.
