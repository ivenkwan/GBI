Phase 10 — Metrics + Explore: per-tenant Cube data queries end-to-end.

Safety property: RLS fail-closed. If the Cube tenant-GUC wiring is imperfect, /load returns zero rows (visible, debuggable) — it can NEVER return another tenant's data. That makes this buildable and verifiable in CI, with live confirmation when Docker returns.

## 1. Per-tenant Cube data path (semantic/cube/cube.js)
- `contextToOrchestratorId: ({ securityContext }) => securityContext?.tenantId ?? "anonymous"` — separate orchestrator (driver pool) per tenant.
- `driverFactory` returning `@cubejs-backend/postgres-driver` (bundled in the cubejs/cube image) configured from CUBEJS_DB_* env PLUS the pg `options` connection parameter: `-c app.current_tenant_id=${tenantId}` — the session GUC applied on every pooled connection, exactly what the RLS policies consume. Requests without a tenant claim (metadata /meta) get the plain driver.
- No queryRewrite tenant filter: hidden (`visible: false`) dimensions can't be filtered, and GUC+RLS already enforces strictly.

## 2. CubeClient: tenant-scoped auth + queries (backend/app/semantic/cube_client.py)
- `_auth_token(tenant_id=None)`: adds `{"tenantId": ...}` claim (Cube surfaces custom claims as securityContext); token cache becomes per-tenant (dict keyed by tenant id + None for anonymous).
- `query(..., tenant_id=None)`: threads tenant into `_request` → token. Metrics metadata stays anonymous.
- Fix the no-op `metric_key = metrics[0].replace(".", ".")` oddity while touching query().
- Cache: new `get_cube_query_result`/`set_cube_query_result` in core/cache.py following existing patterns (key `genbi:{tenant}:cube_query:{sha256 of canonical query JSON}`, TTL QUERY_RESULTS=300).

## 3. Endpoints (backend/app/api/v1/)
- `POST /metrics/query` — real: request {measures (1–5), dimensions?, time_dimensions?, filters?, order?, limit ≤1000, timezone?}; tenant from `user["tenant_id"]`; validates measures against the catalog (400 INVALID_METRIC); response {data, annotation, total, query, latency_ms, cached}; 503 CUBE_UNAVAILABLE on transport errors. Cache wrap get/set_cube_query_result.
- `GET /datasources` — real: cubes from /meta as [{name, title, measures: n, dimensions: n}]; 503 when Cube down. `POST /datasources/test` remains stub (different feature: user-configured external connections).

## 4. Frontend
- api-client: `listMetrics()`, `queryMetrics(req)` + types; validators: MetricSummarySchema (backend shape), MetricQueryRequest/Response schemas.
- `app/explore/page.tsx` (AuthGuard → Explore view): catalog grouped by cube (Badge/Card, metric_type chips), query builder (DropdownMenu as select — no new deps; 1–2 measures, 0–2 dimensions, optional time granularity), results as a Tailwind table, plus a rendered bar chart: build ChartAssemblyInput from result rows → renderChart → ChartCard (reuses the existing chart stack).
- chat-view.tsx: replace the dead `view` toggle with `router.push("/explore")` (Database icon, "Explore metrics" tooltip); simple header on Explore with link back to /chat.
