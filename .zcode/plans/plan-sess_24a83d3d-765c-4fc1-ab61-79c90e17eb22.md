# Phase 27 — Demo Environment CLI (Tasks 139–148)

Plan a demo-environment toolchain for GenBI and record it as **Phase 27** in `todo.md`. Four user-facing capabilities, per the requested scope:

1. **CLI to provision & bring the environment up** → `demo up`
2. **CLI to provision demo data** → `demo seed`
3. **CLI to remove demo data** → `demo unseed`
4. **CLI to reset everything to factory defaults** → `demo reset`

## Design decisions (grounded in repo conventions)

- **One CLI, existing pattern**: `scripts/demo.py` — argparse subcommands, no new CLI framework (repo convention is argparse + `scripts/` + Makefile, like `setup.sh` / `verify.sh` / `seed_test_data.py` / `create_admin.py`). Host-side script is **stdlib-only** (argparse, subprocess, pathlib, urllib) so it works on a machine with just `docker` + `python3` — no `make setup` prerequisite.
- **DB work runs in-container**: the host CLI orchestrates `docker compose` and delegates DB-heavy operations via `docker compose exec -e PYTHONPATH=/app backend uv run python scripts/demo.py <cmd>` — exactly the `make seed` pattern. `scripts/` is already bind-mounted read-only into the backend container (`infra/docker-compose.dev.yml:61`), so no Dockerfile changes. The script detects in-container mode (env marker set by the exec, e.g. `GENBI_DEMO_INTERNAL=1`) and dispatches to the ops package instead of orchestrating compose.
- **Reuse, don't duplicate**: `scripts/gen-env.sh` (env/secrets), the `make migrate` command sequence (alembic + `infra/postgres/rls/*.sql` via `docker exec genbi-postgres psql`), `scripts/setup.sh`'s fresh-volume baseline-stamp logic, `seed_test_data.py`'s generators (deterministic variant), `scripts/embed_schema.py` (per-tenant embeddings + golden examples), `scripts/db_admin.py` (`owner_connect` + `set_tenant_guc`), and `app/services/tenants.py` decommission semantics (unseed).
- **Dedicated demo tenants** (user-confirmed): demo data lives in new tenants marked `tenants.settings = {"demo": true, ...}`. The bootstrap tenant (`admin@genbi.local`) stays pristine. `demo unseed` = marker-driven decommission — precise, safe, and a second demo tenant showcases cross-tenant isolation.
- **Deterministic by default**: fixed seed (default 42) → identical numbers/dates every demo run; `--random` opts out. Fixed date ranges (2024-01-01 → 2026-06-30, same as the existing generators) keep chart axes stable.
- **No LLM spend**: reports/dashboards/conversations are hand-authored against the known deterministic figures. Schema/wiki embeddings are attempted only when `OPENAI_API_KEY` is set (warned + skipped otherwise — existing fail-open paths cover this).

## CLI surface

```
python3 scripts/demo.py up       # or: make demo-up      — provision & start stack
python3 scripts/demo.py seed     # or: make demo-seed    — create demo data
python3 scripts/demo.py unseed   # or: make demo-unseed  — remove demo data
python3 scripts/demo.py reset    # or: make demo-reset   — factory reset
python3 scripts/demo.py status   # or: make demo-status  — health + demo state + credentials
```

### `demo up` (task 140)
Idempotent (healthy stack → print URLs, exit 0). Steps: prereq check (docker + compose v2; python3) → warn (non-fatal) if `ANTHROPIC_API_KEY` missing in `backend/.env` → ensure env files via `scripts/gen-env.sh` (no `--force`; it already refuses overwrite) → images: build, or with `--pull` pull the CI-published pgvector+AGE image from ghcr and retag to `genbi/postgres-pgvector-age:pg16` (skips the slow AGE source compile; backend/frontend still build locally) → `up -d postgres redis`, wait healthy → **fresh-volume detection + `alembic stamp 0001_baseline`** (replicating `setup.sh` logic) → `alembic upgrade head` + apply `infra/postgres/rls/*.sql` → `up -d` full stack → poll backend `/health/ready` + frontend :3000 → run `scripts/verify.sh` (skip with `--no-verify`) → print URLs (backend :8000/docs, frontend :3000, Cube :4000, Grafana :3001, Prometheus :9090) + hint to run `demo seed`.

### `demo seed` (tasks 141–142)
Flags: `--tenants N` (default 2), `--seed INT` (default 42), `--random`, `--append`, `--skip-embeddings`. Replace-by-default idempotency (existing demo tenants are decommissioned + recreated unless `--append`).

Per demo tenant (default roster: **Acme Analytics** `demo-acme`, **Globex Retail** `demo-globex`; extras generated):
1. Tenant row with `settings = {"demo": true, "seed": <seed>, "seeded_at": <iso>, "demo_version": 1}` (owner role via `db_admin.owner_connect`).
2. Users: `admin@demo-acme.test` / `analyst@…` / `viewer@…` — fixed password `Demo123!` (bcrypt via `app.core.security`), roles `["admin","user"]` / `["user"]` / `["viewer"]`.
3. Deterministic analytics: `random.Random(seed + tenant_index)` generators derived from `seed_test_data.py` (same 10 tables, same default row counts, stable UUIDs via `uuid5` for FK sanity).
4. Per-tenant `schema_embeddings` + golden `agent_examples` — **small backward-compatible change: add `--tenant-id` to `scripts/embed_schema.py`** (default stays the sentinel), then run it per demo tenant with `--examples`. Skipped with a prominent warning when `OPENAI_API_KEY` is unset.
5. Wiki: 3–5 markdown pages per tenant (metric glossary, data caveats) — parameterized INSERTs, owner + tenant GUC; `wiki_embeddings` left empty when no OpenAI key (keyword fallback already works).
6. Report (3 sections with hand-authored chart specs matching the deterministic figures — revenue by region bar, units over time line, top products) + dashboard pinning its sections.
7. Sample conversation: 1 thread, 2 turns (user question + assistant narrative citing the deterministic numbers).
8. Redis purge: SCAN+DEL tenant-scoped keys for demo tenants via `docker exec genbi-redis redis-cli`.

Finish by printing the credentials table, seeded row counts, suggested demo queries, and any capability warnings.

### `demo unseed` (task 143)
Requires the stack up (clear error otherwise). Selects all tenants with `settings->>'demo' = 'true'` and removes each through the decommission path from `app/services/tenants.py` (FK cascade + per-table analytics cleanup + `admin_audit` row; `audit_log` retention is by design — `demo reset` is the true clean slate). Purges Redis keys. Post-checks + summary: zero demo-marked tenants remain; bootstrap tenant and `admin@genbi.local` untouched.

### `demo reset` (task 144)
Destructive — requires `--yes` or interactive confirm. `docker compose down -v` (drops `postgres_data` + `flint_data`) → regenerate env via `gen-env.sh --force` **while preserving user-supplied keys** (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `LANGFUSE_*`) from the previous `backend/.env`; `--nuke-env` wipes them for a true factory state → same bring-up path as `demo up` (fresh volume → `init.sql` bootstrap, stamp, migrate, verify) → print fresh demo credentials (`admin@genbi.local` / `admin123`) + hint to re-run `demo seed`.

### `demo status` (task 145)
`compose ps` + health-endpoint polls (stdlib urllib) + demo-tenant marker scan via `docker exec genbi-postgres psql` + credentials + URLs + seeded/not-seeded state.
